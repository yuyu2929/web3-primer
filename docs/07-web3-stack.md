# 07 Web3 技术栈与身份

> **导航**：[← 上一章：06 智能合约与 DApp](06-smart-contracts.md) · [目录](../README.md) · [下一章：08 风险、局限与展望 →](08-risks-future.md)

> 把前几章的零件拼在一起：钱包、存储、索引、跨链……一个完整的 Web3 应用由哪些模块组成？本章给出全景。

## 1. Web1 / Web2 / Web3：一次范式对比

| | Web1（只读） | Web2（读写） | Web3（读写 + 拥有） |
| --- | --- | --- | --- |
| 内容由谁产生 | 少数站长 | 用户产生，平台托管 | 用户产生，链上确权 |
| 身份 | 匿名 | 平台账号（被平台控制） | 钱包地址（用户自己控制） |
| 数据 | 静态页面 | 平台集中存储与支配 | 链上/去中心化存储，公开可验证 |
| 信任 | 相信网站 | 相信平台 | 相信协议与密码学 |
| 典型形态 | 门户网站 | 社交媒体、电商 | DApp、DeFi、DAO |

Web3 不是「把网站搬上链」，核心转变是**所有权的回归**：你的身份、资产、数据由你掌控，平台无法单方面封禁或篡改。

## 2. 钱包：Web3 的入口与身份

钱包是用户进入 Web3 的第一站，它同时承担两个角色：

1. **钥匙串**：管理私钥，签名交易；
2. **身份凭证**：地址即身份，所有链上行为都挂在这个地址下。

### 签名登录（Sign-In with Ethereum）

Web2 登录是「输入账号密码 → 平台确认」。Web3 登录是：

```text
网站：请用你的钱包签名这串文本
用户：钱包弹出确认 → 私钥签名 → 网站验签通过 → 登录成功
```

整个过程**网站不接触你的私钥**，且可以验证「该地址确实由你控制」。这就是 SIWE（EIP-4361）的基本思想——**用签名代替密码，身份不再依赖任何平台的数据库**。

### 常用钱包形态

| 形态 | 例子 | 特点 |
| --- | --- | --- |
| 浏览器插件 | MetaMask、Rabby | 桌面端最常用，开发者必备 |
| 移动 App | Trust Wallet、Rainbow | 手机端体验好 |
| 硬件钱包 | Ledger、Trezor | 私钥离线，最安全 |
| 智能合约钱包 | Safe、Argent | 支持恢复、多签、社交恢复，适合机构与长期持有 |

## 3. 去中心化存储：内容放哪里

区块链存状态很贵，不适合存大文件。于是存储分层：

- **链上**：只存关键状态（余额、所有权、哈希）；
- **链下/去中心化存储**：存大内容，用哈希锚定到链上。

典型方案：

| 方案 | 思路 | 特点 |
| --- | --- | --- |
| **IPFS** | 内容寻址的分布式文件系统 | 文件按内容哈希定位，去中心分发 |
| **Arweave** | 一次性付费、永久存储 | 面向永久保存 |
| **Filecoin** | 激励层的存储市场 | 矿工提供存储赚取 FIL |

内容寻址还有个隐藏福利：**内容不可变且可验证**——文件内容一旦改变，地址（哈希）就变，天然防篡改。

## 4. 索引与查询：链上数据怎么读

链本身只提供「按交易/区块读取」的原始接口，应用需要「按业务查询」（如：这个地址持有哪些 NFT？）。**直接扫链又慢又贵**，于是有了索引层：

- **The Graph**：开发者定义子图（Subgraph），把链上事件整理成可查询的数据，通过 GraphQL 提供 API；
- 它扮演 Web3 世界的「搜索引擎/数据仓库」，是 DApp 架构里常被忽略却必不可少的模块。

## 5. 域名与身份：让人可读

地址是一串 `0x...` 的十六进制，人类记不住。于是有了链上域名：

- **ENS（Ethereum Name Service）**：把 `alice.eth` 映射到地址，转账、登录都可读；
- 域名本身是 NFT，可以在二级市场交易。

## 6. 跨链：孤岛之间的桥

链不止一条：以太坊、Solana、Polygon、Arbitrum……各链之间资产与数据无法天然互通。**跨链桥（Bridge）**解决这个问题：

```text
链 A：锁定/销毁资产 ──> 桥的验证机制 ──> 链 B：铸造等量资产
```

桥的本质是「在链 A 上托管，在链 B 上发行凭证」。**桥是黑客攻击的重灾区**——托管资产规模巨大，而验证机制往往薄弱。跨链时务必选择成熟方案，并理解其信任模型（托管式 vs 轻量验证式）。

## 7. 组织形态：DAO

如果「公司是中心化组织的终极形态」，那 **DAO（去中心化自治组织）**就是链上组织：

- 规则写进智能合约（提案、投票、金库管理）；
- 成员用**治理代币**投票，票数即话语权；
- 金库由多签/合约管理，**没有 CEO 可以单独挪用**；
- 局限：投票参与率低、治理攻击（买票控盘）、法律地位模糊。

DAO 目前仍是「半成品」，但「代码治理组织」的方向已明确。

## 8. 一条链上的完整 DApp 架构图

```text
┌───────────────────────────────────────────────┐
│ 用户                                          │
│   钱包（身份 + 签名 + 私钥管理）               │
└───────────────┬───────────────────────────────┘
                │ 签名交易 / 签名登录
┌───────────────▼───────────────────────────────┐
│ 前端 DApp（React/Vue 等，可托管在 IPFS）        │
└───────────────┬───────────────────────────────┘
                │ RPC 调用 / GraphQL 查询
┌───────────────┼───────────────────────────────┐
│ 链上：智能合约（状态与规则）                    │
│ 链下：存储（IPFS/Arweave）+ 索引（The Graph）  │
│ 外部：预言机（价格/数据）+ 跨链桥               │
└───────────────────────────────────────────────┘
```

## 本章小结

- Web3 的核心是**所有权回归**：身份、资产、数据由用户掌控；
- 钱包 = 私钥管理 + 身份凭证，**签名即登录**；
- 存储分层（链上状态 + 链下内容）、索引层（The Graph）补齐 DApp 骨架；
- 跨链桥与 DAO 是仍在进化中的前沿模块。
