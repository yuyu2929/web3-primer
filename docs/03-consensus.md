# 03 共识机制

> **导航**：[← 上一章：02 密码学前置知识](02-cryptography-basics.md) · [目录](../README.md) · [下一章：04 比特币 →](04-bitcoin.md)

> 每个节点都保存一份账本副本——可万一大家手里的账本**不一样**怎么办？共识机制回答的正是这个问题：**在没有权威的情况下，如何让全网对同一份状态达成一致？**

## 1. 问题的本质：拜占庭将军问题

设想几支军队要协同进攻一座城，只能靠信使通信。问题是：将军里可能有**叛徒**，信使也可能被截获伪造。忠诚的将军如何确保大家最终做出**一致且正确**的决定？

这就是经典的「拜占庭将军问题」。映射到区块链上：

- 每个节点都是将军；
- 网络中的节点可能作恶（攻击者）；
- 节点之间的消息可能被篡改或延迟；
- 我们要的是：**所有诚实节点最终接受同一条链**，且这条链没有被作恶者主导。

共识机制就是「如何选出一个记账者/如何确认一笔账」的规则。不同机制给出了不同答案，它们的共同点是：**让作恶变得比诚实更昂贵**。

## 2. 工作量证明（Proof of Work, PoW）

比特币采用 PoW。核心思想是**「谁干活多，谁说了算」**：

1. 打包候选区块的节点，必须求解一个数学难题：找到一个随机数（nonce），使得「区块内容 + nonce」的哈希满足一个**难度目标**（比如前面必须有 N 个 0）。
2. 这个难题没有捷径，只能一遍遍试——**消耗的是真实电力和算力**。
3. 谁先解出，谁就把区块广播给全网；其他节点验证后，接在自己账本后面，然后开始挖下一个区块。
4. 如果出现两条竞争链（分叉），约定**最长链为准**——更准确地说，是**累计工作量最大**的那条：哪条链积累的难度总量更多，就采纳哪条（链长短只是它的近似说法）。

### 为什么 PoW 能防作恶

攻击者想改写历史，就必须**重做**那个区块之后的所有工作量，并且**追上并超过**诚实节点正在延长的链。在攻击者算力占比不足 50% 的情况下，追上诚实链的概率随时间**指数级**下降。

这也引出了著名的 **51% 攻击**：如果一方控制了全网超过一半的算力，理论上可以：

- 双花（花掉一笔钱，然后回滚这笔交易）；
- 拒绝打包别人的交易。

但它**不能**：偷走别人的币、伪造没有私钥的交易。51% 攻击的代价是「维持统治算力」的巨额成本，所以它更像一种理论威胁与经济博弈，而非日常风险。

### 难度调整

为了让出块速度大致稳定（比特币约 10 分钟一块），网络会根据近期的总算力，周期性调整难度目标：算力变强，难度上调；算力变弱，难度下调。比特币的周期是每 **2016 个区块**（约两周）调整一次，调整幅度上限为 4 倍。这一机制让链对全网算力的变化保持韧性。

## 3. 权益证明（Proof of Stake, PoS）

PoW 的代价是大量能源消耗。PoS 换了一个思路：**「谁质押得多，谁说了算」**。

1. 节点（验证者）先把资产**质押（Stake）**进合约，作为保证金；
2. 系统按质押量和随机因素选出下一个出块者（不是比算力，而是比「身家」+ 运气）；
3. 作恶会被**罚没（Slash）**质押金——作恶成本是实打实的资产损失；
4. 诚实出块则获得区块奖励和手续费。

以太坊在 2022 年通过「合并（The Merge）」从 PoW 切换到 PoS，质押门槛为 32 ETH 成为验证者（也支持通过质押池参与）。

### PoW vs PoS 一览

| 维度 | PoW | PoS |
| --- | --- | --- |
| 记账权依据 | 算力 | 质押资产 |
| 能源消耗 | 高 | 低（约可忽略） |
| 作恶代价 | 电力与硬件沉没成本 | 质押金被罚没 |
| 攻击者画像 | 掌握算力者 | 掌握大量质押者 |
| 典型代表 | 比特币、早期以太坊 | 以太坊（合并后）、Solana、Cardano |

两种机制都在回答同一个问题，只是把「入场券」从算力换成了资产。**「去中心化」的核心在于：没有任何单一实体能稳定地拿到多数记账权。**

## 4. 分叉：当规则发生分歧

「共同规则」是共识的前提，但规则不是一成不变的。当社区对「规则该不该改、怎么改」产生分歧时，就会出现**分叉（Fork）**：

- **软分叉**：新规则向后兼容，老节点还能继续验证新区块。通常只需多数矿工/验证者升级即可平滑过渡。
- **硬分叉**：新旧规则不兼容，链一分为二，各自继续运行。典型案例：2017 年比特币社区对区块大小意见分裂，诞生了 BCH（Bitcoin Cash）；2016 年以太坊因 The DAO 事件回滚历史，分裂出 ETC（Ethereum Classic）。

分叉本身不是坏事——它是**治理机制**的一部分：当协议层面的分歧无法调和时，市场用脚投票，两条链各走各路。

## 5. 最终性：交易什么时候「真的定了」

中心化系统里，银行说「转账成功」就是终局。去中心化系统里，交易的确认是**概率性的**：它被打包进区块只是初步确认，还要等后续区块不断「压」上来。

- 一笔交易后面叠的确认块越多，被回滚的可能性越小；
- 比特币惯例等 6 个确认（约 1 小时）才算「稳妥」；
- PoS 链通常有明确的**最终性（Finality）**机制（如以太坊的 Casper FFG）：一旦某个检查点被最终确定，就不会再被回滚。

理解「确认是一个渐强过程」很重要：它解释了为什么链上转账比支付宝慢，也解释了为什么「0 确认」交易有风险。

## 本章小结

- 共识机制解决**无权威下的状态一致**问题；
- PoW 用算力说话，PoS 用质押说话，共同点是**让作恶无利可图**；
- 分叉是治理分歧的正常产物，硬分叉会分裂出新链；
- 链上确认是概率渐强的过程，最终性机制让 PoS 链更可预期。
