# 05 以太坊

> **导航**：[← 上一章：04 比特币](04-bitcoin.md) · [目录](../README.md) · [下一章：06 智能合约与 DApp →](06-smart-contracts.md)

> 比特币是一本「转账账本」，以太坊则是一台**全球共享、人人可编程的计算机**。它的诞生把区块链从「数字货币」推进到了「可编程世界」。

## 1. 从「记账」到「编程」

比特币的脚本只能做转账这类有限操作。2013 年，Vitalik Buterin 提出以太坊：为什么不把链上账本升级为**可编程的状态机**——任何人都能部署一段代码（智能合约），由全网节点共同执行，执行结果成为新的链上状态？

以太坊由此提出一个核心概念：**EVM（Ethereum Virtual Machine，以太坊虚拟机）**。

- 智能合约运行在 EVM 里，用 Solidity 等语言编写，编译成字节码；
- **每个节点都执行同一段代码，得到同一结果**——这是「世界计算机」的含义；
- 代码一旦部署，就按代码执行，**没有后门、没有 CEO、没有客服**。

## 2. 账户模型：EOA 与合约账户

比特币用 UTXO，以太坊用**账户余额模型**——更接近我们熟悉的银行账户。账户分两类：

| | 外部账户（EOA） | 合约账户（Contract） |
| --- | --- | --- |
| 谁控制 | 私钥持有者 | 合约代码 |
| 能否发起交易 | ✅ 可以 | ❌ 只能被调用 |
| 有无代码 | 无 | 有（部署时写入） |
| 典型用途 | 用户转账 | 承载业务逻辑（代币、借贷、拍卖……） |

用户的每笔操作都是一笔**交易**：`from` 是发起账户，`to` 可以是另一账户或合约地址。合约账户无法「主动行动」，只能等待被交易触发——这是理解 DApp 架构的关键。

## 3. Gas：计算是有成本的

「世界计算机」的算力不是免费的——网络靠 **Gas** 机制为每一次计算定价：

- 每一步操作（存储、运算、转账）都有对应的 Gas 消耗；
- 交易发起者支付 `Gas 用量 × Gas 单价`，单位用 **Gwei**（10⁻⁹ ETH）计价；
- Gas 用得多、单价出得高的交易，优先被打包。

### Gas 的作用

1. **防止滥用**：没有 Gas，攻击者可以无限刷合约，把网络堵死；
2. **按需定价**：网络越拥堵，Gas 单价越高，市场自动调节；
3. **防死循环**：Gas 耗尽即交易失败回滚，防止合约无限执行。

### EIP-1559（2021 年伦敦升级）

手续费机制升级为「基础费 + 小费」：

- **基础费**由网络拥堵程度动态调整，**直接销毁**（不再归矿工/验证者）；
- **小费**（Priority Fee）付给验证者，作为打包激励；
- 结果：ETH 从「支付手续费」变成了「燃烧通缩」——网络越活跃，销毁越多。

## 4. 合并：从 PoW 到 PoS

2022 年 9 月，以太坊完成**「合并（The Merge）」**，共识机制从 PoW 切换为 PoS（详见第 3 章）：

- 验证者需质押 **32 ETH** 参与出块；
- 能源消耗下降 **99% 以上**；
- 为后续的**分片 / 数据可用性扩展**铺路。

合并后以太坊由两层协同：**执行层**（跑 EVM 与应用）与**共识层**（跑 PoS 与最终性）。2024 年的 EIP-4844（proto-danksharding）又为 Layer 2 增加了廉价的数据可用性空间（blob），可以理解为「给二层用的数据层」——但它不是合并时就有的第三条链上轨道。

## 5. 代币标准：链上世界的「货币」与「资产」

以太坊的杀手锏是**可编程代币**——任何人都能发行自己的代币，且有统一标准保证互操作性：

| 标准 | 用途 | 要点 |
| --- | --- | --- |
| **ERC-20** | 同质化代币（FT） | 每个单位等价、可分割，如 USDC、各类治理代币 |
| **ERC-721** | 非同质化代币（NFT） | 每个 token 独一无二，如数字藏品、游戏道具 |
| **ERC-1155** | 混合代币 | 一套合约同时管理同质与非同质资产，游戏场景常用 |

代币标准的伟大之处：**发行方只需实现标准接口**，钱包、交易所、DeFi 协议就能自动识别与支持——这构成了以太坊「资产互联网」的底层协议层。

## 6. 简单看一个合约长什么样

一个最小 ERC-20 风格合约的骨架（示意，仅帮助建立直觉）：

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

contract SimpleToken {
    mapping(address => uint256) public balances;

    // 转账：减少自己余额，增加对方余额
    function transfer(address to, uint256 amount) public {
        require(balances[msg.sender] >= amount, "insufficient balance");
        balances[msg.sender] -= amount;
        balances[to] += amount;
    }
}
```

关键点：`msg.sender` 是调用者地址（由签名验证保证真实性）；`require` 是前置条件检查；`mapping` 是状态存储。合约就是**由数据 + 规则构成的公共程序**，人人可查、不可篡改。

> 注意：这只是**教学骨架**，不是完整的 ERC-20。真实标准还需要 `totalSupply`、`Transfer`/`Approval` 事件、`decimals`/`symbol`/`name` 元数据，以及 `approve`/`transferFrom`（授权与代转）和布尔返回值——缺了事件，钱包和区块浏览器就看不到你的转账。

## 7. 以太坊的局限

- **吞吐量低**：单链每秒约 15–30 笔交易，远不及中心化数据库；
- **Gas 波动**：拥堵时手续费昂贵，普通用户难以承受；
- **状态爆炸**：每个节点都存全量状态，链越用越「重」；
- **升级之痛**：协议升级需要全节点协调，历史包袱（如曾发生过的网络拥堵事故）不易甩掉。

这些局限催生了 **Layer 2（二层网络）**与各类扩展方案——第 8 章详细展开。

## 本章小结

- 以太坊 = **可编程状态机**，EVM 让「代码即法律」成为可能；
- 两种账户：**EOA（人）** 与 **合约账户（代码）**；
- **Gas 机制**为计算定价并防滥用，EIP-1559 引入销毁通缩；
- 代币标准（ERC-20/721/1155）构成资产互联网的协议层；
- 局限催生扩展方案，链上生态仍在演进。
