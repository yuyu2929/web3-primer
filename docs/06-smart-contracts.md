# 06 智能合约与 DApp

> **导航**：[← 上一章：05 以太坊](05-ethereum.md) · [目录](../README.md) · [下一章：07 Web3 技术栈与身份 →](07-web3-stack.md)

> 智能合约是「跑在链上的程序」，DApp（去中心化应用）则是「前端 + 智能合约」的完整应用。本章把它们拆开讲透。

## 1. 智能合约：一份会自己执行的协议

「智能合约」这个词容易让人想到法律合同，其实它更接近**自动售货机**：

- 你投入硬币、按下按钮，机器按预设逻辑吐出货品——没人需要信任店员；
- 智能合约就是「链上的自动售货机」：**条件满足，自动执行；规则公开，人人可查；结果不可逆转**。

### 特性

| 特性 | 含义 |
| --- | --- |
| 确定性 | 同样的输入，全网执行得到同样的结果 |
| 公开透明 | 代码与状态对所有人可见 |
| 不可篡改 | 部署后代码不可更改（除非合约本身留有升级接口） |
| 无信任中介 | 执行不依赖任何机构的善意 |
| 无国界 | 全球任何地址都能调用 |

### 代价

代码即法律，意味着**代码的 bug 就是法律的漏洞**。历史上著名的 The DAO 事件（2016 年，约 6000 万美元 ETH 因合约漏洞被卷走）说明：合约开发者必须把安全当作第一优先级，而不是功能。

## 2. DApp 的架构：洋葱模型

一个典型 DApp 分三层：

```text
┌─────────────────────────────┐
│  前端（网页 / App / 钱包 UI）│
└───────────┬─────────────────┘
            │ 调用（通过钱包签名）
┌───────────▼─────────────────┐
│  智能合约（链上状态与规则）   │
└───────────┬─────────────────┘
            │ 读取链上数据
┌───────────▼─────────────────┐
│  区块链网络（共识 + 状态存储）│
└─────────────────────────────┘
```

与 Web2 应用的本质区别：**后端不是你的服务器，而是全球节点共同维护的链**。前端可以托管在任意地方（甚至 IPFS），数据与逻辑在链上。

### 用户如何与 DApp 交互

1. 用户打开 DApp 网页，网页请求连接**钱包**（如 MetaMask）；
2. 用户点击「转账 / 铸造 / 质押」等操作；
3. 钱包弹出确认框，展示交易详情（Gas、金额）；
4. 用户用**私钥签名**，交易广播上链；
5. 前端轮询链上状态，展示结果。

关键点：**每一次状态变更都需要用户钱包签名**——用户的资产由用户自己授权，应用方无法擅自扣款。

## 3. 预言机：链下数据进链上的桥

智能合约有个先天缺陷：**它只能读取链上数据**。可「天气」「股价」「某场比赛结果」都在链下——合约如何知道？

答案是**预言机（Oracle）**：

```text
链下数据源（天气 API、交易所价格）
        ↓
预言机网络（去中心化的数据报送者）
        ↓
链上合约（读取可信数据并执行逻辑）
```

中心化预言机是单点风险（报错、被操纵），因此出现了去中心化预言机网络（如 Chainlink）：多个独立数据源交叉验证，多数一致才上链。**「数据可信」与「计算可信」同样重要**——这就是 DeFi 依赖预言机的根本原因。

## 4. DeFi：去中心化金融的原语

DeFi（Decentralized Finance）是当前智能合约最大的应用场景，它用合约复刻传统金融，但去掉中介。几个核心原语：

### 4.1 去中心化交易所（DEX）与 AMM

传统交易所靠**订单簿**撮合买卖双方。链上方案 **AMM（自动做市商）**另辟蹊径：

- 资金池里同时存有 A、B 两种资产（如 ETH 与 USDC）；
- 价格由池内数量比例按公式自动决定（如恒定乘积公式 `x × y = k`）；
- 用户直接与**池子**交易，不需要对手方；
- 任何人可以**提供流动性**（存入资产），按份额分取手续费。

AMM 的伟大之处：**把「做市商」变成了任何人都能参与的程序**。

### 4.2 借贷协议

- 用户**超额抵押**存入资产（如存入 ETH，借出 USDC）；
- 利率由资金利用率动态调节；
- 抵押率跌破阈值，触发**清算**——系统自动卖掉抵押品还债；
- 全程无人工审批，规则写死在合约里。

### 4.3 质押与收益

- 质押（Staking）：锁定代币支持网络/协议，换取奖励；
- 流动性挖矿：存入资产到协议，获得协议代币激励；
- 收益聚合器：自动把资金调度到最优收益策略。

### DeFi 的风险提示

- **无常损失**：AMM 做市时价格波动可能导致相对直接持有更亏；
- **清算风险**：借贷未及时补抵押，抵押品可能被低价清算；
- **合约风险**：协议被黑、rug pull（跑路）屡见不鲜；
- **预言机操纵**：价格源被操纵会触发连锁清算。

DeFi 的收益不是白来的——**每一个 yield 背后都有一个风险定价**。

## 5. NFT：非同质化资产的载体

NFT 把「独一无二」带上链：

- 每个 token 有独立的 `tokenId` 与元数据（图片、视频、属性）；
- 所有权记录在链上，可验证、可转让；
- 常见场景：数字藏品、游戏资产、会员凭证、域名（如 ENS）。

NFT 的真正价值不在「炒图」，而在**可编程权益**：持有某 NFT 才能进入某社区、获得某空投、参与某治理——它是 Web3 身份的组成部分。

## 6. 一个最小 DApp 的开发流程

给想动手的你一条最短路径（对应第 5 章的合约骨架）：

```text
1. 用 Solidity 写合约（如上面的 SimpleToken）
2. 用 Foundry / Hardhat 本地编译 + 测试
3. 部署到测试网（如 Sepolia），用测试币验证
4. 写一个简单前端（如 React + ethers.js / viem）
5. 连接钱包，调用合约，完成闭环
```

测试网是开发者的游乐场：免费测试币、完整的主网体验，是学习成本最低的入口。

## 本章小结

- 智能合约 = **公开、自动、不可篡改的链上程序**；
- DApp = 前端 + 合约，**后端是链而非服务器**；
- 预言机把链下数据安全地搬上链；
- DeFi 用 AMM、借贷、质押等原语重构金融，**收益与风险一体两面**；
- NFT 与 ENS 让「数字资产」与「数字身份」成为可编程权益。
